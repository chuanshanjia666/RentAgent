## 二、项目目标

### 2.1 总体目标

构建一个功能完整的在线房屋租赁平台，并在传统租赁业务流程之上叠加 AI 智能体能力，使租客能够通过自然语言完成找房、咨询与签约辅助，使房东获得智能定价与房源管理支持，使管理员获得 AI 辅助审核能力。

### 2.2 可度量目标

1. 完成"租客—房东—管理员"三端功能，核心业务闭环（发布房源 → 找房 → 预约看房 → 在线签约 → 评价）可完整走通；
2. AI 智能体上线 4 项核心能力：AI 找房助手、智能客服、合同解读、智能定价建议；
3. 常规页面接口响应时间 ≤ 2 秒，AI 对话首字响应 ≤ 3 秒；
4. 完成高保真原型、数据库设计文档、接口文档与测试报告。

> 注（v1.1）：上述目标中各环节/能力的交付刚性以《需求分析矩阵》优先级为准——核心闭环中的"评价"（FR-20）与 AI 能力中的合同解读（FR-14）、智能定价建议（FR-15）为 P1（演示前必须完成），其余为 P0（Must have）；目标 3 的性能口径以 NFR-01、NFR-02 为准。

## 三、项目范围确认

### 3.1 范围内（本期实现）

| 类别 | 内容 |
| ---- | ---- |
| 用户与权限 | 注册登录、角色区分（租客/房东/管理员）、实名认证、个人信息管理 |
| 房源管理 | 房东发布/编辑/上下架房源、图片上传、管理员审核 |
| 房源检索 | 多条件筛选、关键词搜索、地图找房、个性化推荐 |
| AI 智能体 | AI 找房助手（自然语言找房）、智能客服（RAG 知识库问答）、合同智能解读、房东智能定价建议、虚假房源检测（AI 辅助审核，P2） |
| 交易履约 | 预约看房、电子合同在线生成与签约、订单与租金记录管理 |
| 互动评价 | 房源/房东评分评价、站内消息通知 |
| 后台管理 | 用户管理、房源审核、评价管理、数据统计看板 |

### 3.2 范围外（本期不做，避免范围蔓延）

- ❌ 在线支付与资金托管（租金支付仅做记录，不对接真实支付渠道）；
- ❌ 移动端 App / 小程序（以响应式 Web 覆盖移动浏览场景）；
- ❌ 自研大模型训练与微调（统一调用第三方大模型 API）；
- ❌ 电子签章的法律效力对接（合同签署做流程演示，不接入 CA 认证）；
- ❌ 智能门锁、VR 看房等智能硬件与 3D 能力。

### 3.3 假设与约束

| 类型 | 内容 |
| ---- | ---- |
| 假设 | 大模型 API 在项目周期内持续可用且免费/低成本额度满足开发演示需要 |
| 约束 | 系统需在学期/项目周期内完成开发与演示；团队具备 Java、Vue、Python 基础 |
| 合规约束 | 用户个人信息收集遵循最小必要原则；AI 生成内容需标识并可追溯 |

## 四、用户角色确认

| 角色 | 描述 | 核心诉求 |
| ---- | ---- | -------- |
| 租客 | 平台的主要消费者 | 快速找到符合预算与通勤条件的真实房源，签约前获得风险提示 |
| 房东 | 房源的提供者 | 高效发布与管理房源，获得合理定价参考，减少空置 |
| 平台管理员 | 平台运营者 | 高效审核房源与处理纠纷，掌握平台运营数据 |
| AI 智能体 | 系统内置的智能服务角色 | 以自然语言为三端用户提供问答、检索、分析与工具执行服务 |

## 五、技术方案确认

| 项目 | 确认结论 |
| ---- | -------- |
| 前端 | React 18 + TypeScript + Vite + Ant Design 5 + ECharts（v1.2 起为最终前端基线，与原型载体统一；原 Vue 3 + Element Plus 方案废止；v1.3 起前端全面采用 TypeScript） |
| 客户端形态 | 两种分发形态共用同一份构建产物：**浏览器 Web 版**（静态资源由 Nginx 托管）与 **桌面端**（Electron 外壳直接打开 Web 版页面，仅补充后端服务地址，不新增界面与功能）（v1.4 起） |
| 后端 | Spring Boot 3.x + MyBatis-Plus + Spring AI / LangChain4j |
| 数据库 | MySQL 8（业务数据）+ Redis 7（缓存/会话）+ 向量检索（Redis Stack / PGVector） |
| 大模型 | **不绑定厂商**：经 LLM 网关按协议接入任意兼容模型（OpenAI Chat Completions / Anthropic Messages / OpenAI Responses 三协议），端点、模型、Key 均可配置，换模型只改配置（v1.5 起口径明确） |
| AI 能力实现 | Function Calling 工具调用 + RAG 检索增强 + 多轮对话记忆 |
| 鉴权安全 | JWT + RBAC 角色权限模型 + HTTPS + 密码 BCrypt 加密 |
| 部署 | Docker Compose 单机部署（Nginx + 前端静态资源 + 后端服务 + 数据库）；桌面端以安装包形式随交付物分发（AppImage / deb），运行需连接后端服务 |

> 注（v1.2，2026-09-14）：前端基线经项目组确认由 Vue 3 调整为 React 18 + Ant Design 5（与高保真原型载体统一，降低双栈维护成本）；大模型经 LLM 网关接入智谱 GLM-5.3-flash（Anthropic 兼容协议），网关保留三协议后端一键切换能力。其余基线不变。

> 注（v1.3，2026-09-15）：前端正式代码（`frontend/`）由 JSX 全面迁移为 TypeScript（strict 模式，`tsc --noEmit && vite build`），15 页视图与全部公共模块类型化，构建与浏览器实测通过；视觉与交互与 v1.2 基线一致。其余基线不变。

> 注（v1.5，2026-09-17）：明确大模型口径为**模型无关**——系统通过 LLM 网关按协议适配任意兼容模型，交付物中不把系统表述为某一厂商方案的实现；当前演示通道为模型聚合网关（OpenAI Chat Completions 协议）+ `deepseek/deepseek-v4.1-flash`，切换模型/供应商只需改配置（`AI_BACKEND` 或 `AI_PROTOCOL`+`AI_BASE_URL`+`AI_MODEL`）。此前版本注中出现的厂商与模型名，仅为该日期演示环境的取值，不构成系统依赖。其余基线不变。
>
> 注（v1.4，2026-09-17）：前端交付形态确认为两版——**浏览器 Web 版**与 **Electron 桌面端**。两版共用同一份构建产物（`frontend/dist`），桌面端仅增加窗口外壳并把后端服务地址注入页面（因为 `file://` 下相对路径无法请求后端），**不新增任何界面或业务功能**；打包产物为 AppImage / deb。前端代码侧相应改造：接口基址与图片地址改为按运行环境解析（`src/runtime.ts`），构建基址改为相对路径。其余基线不变。

## 一、会议议题

1. 概要设计说明书（架构、模块划分、类设计）评审；
2. 数据库 19 张表结构、字段与 ER 关系确认；
3. AI 层架构专项：LLM 网关协议适配方案与知识库 RAG 方案；
4. 前端页面与接口契约对齐。

## 二、会议结论

1. **总体架构通过**：B/S 前后端分离，自上而下四层（表现层 / 业务层 / 智能体层 / 数据层）；桌面端
   Electron 仅包装 Web 版页面，不新增业务功能。
2. **数据库 19 张表确认**：含 `sys_user`、`house`、`house_image`、`viewing_appointment`、`lease_order`、
   `rent_bill`、`contract`、`review`、`favorite`、`realname_auth`、`notification`、`report`、`audit_log`、
   以及 AI 侧 `ai_provider_config` / `ai_chat_session` / `ai_chat_message` / `ai_analysis`、知识库
   `kb_document` / `kb_chunk` 等；`house.facilities` 采用 JSON 列，实体侧统一为 `List<String>`。
3. **AI 层方案定稿**：
   - 自研双通道网关 `LlmGateway` + `EmbeddingGateway`，支持三种 LLM 协议
     （openai-chat-completions / anthropic-messages / openai-responses）；
   - 解决"同一轮正文与 tool_calls 并存时丢调用"问题：正文与工具调用分别累积后合并；
   - 知识库采用稠密向量 RAG（bge-m3 / OpenAI Embedding），余弦相似度 + 阈值过滤；
   - 明确纪律：**AI 能力必须接真实模型，未配置或失败统一返回 4001，不做规则/模拟兜底**。
4. **接口契约**：统一响应 `{code, message, data}`；错误码分段 1xxx/2xxx/3xxx/4xxx/5xxx；分页统一 `PageVO`；
   列表页一律服务端分页，上限 50。

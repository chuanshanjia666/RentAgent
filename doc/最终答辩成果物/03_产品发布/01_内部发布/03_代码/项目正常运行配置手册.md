# RentAgent 项目正常运行配置手册

> 本文档指导评审老师与使用者在一台全新机器上从零启动 RentAgent，并说明 AI 能力的配置方法。
> 项目版本：v1.10；适用范围：课程设计答辩演示与二次部署。

## 三、快速启动（三步）

### 步骤 1：启动基础设施（MySQL + Redis）

```bash
# 在项目根目录执行（务必点名服务，裸 docker compose up -d 会连带把 server 容器一起起来）
docker compose up -d mysql redis
```

首次启动自动建库建表（`docker/mysql-init/01_schema.sql`）。等待 MySQL 健康检查通过（`docker compose ps` 看状态）。

### 步骤 2：启动后端（端口 8080）

```bash
cd server
./run-dev.sh                 # 本地开发启动脚本（Windows 下用 git bash 或改执行 mvn）
# 或手动：
mvn spring-boot:run
```

启动验证：

```bash
curl http://localhost:8080/api/v1/ai/engine
# 配置了模型时返回：{"engine":"openai-chat-completions:deepseek/..."}
# 未配置模型时返回 4001 并提示注入凭据（本系统不提供任何规则/模拟兜底，属预期行为）
```

接口文档（Swagger）：<http://localhost:8080/swagger-ui.html>

### 步骤 3：启动前端（端口 5173）

```bash
cd frontend
npm install
npm run dev
```

浏览器访问 <http://localhost:5173>（**请用 `localhost` 而非 `127.0.0.1`**：两者被浏览器视为不同来源，
后端 CORS 白名单之外的来源会被拒绝，表现为登录无反应）。

### 步骤 3.1：桌面端（可选）

```bash
cd frontend
npm run build:web          # 构建 Web 产物 frontend/dist
npm run start:desktop      # 用原生窗口打开 dist
npm run dist:desktop       # 打包安装包 → frontend/release/（AppImage + deb）
```

## 四、环境变量与配置

### 4.1 数据库 / 缓存 / 安全

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MYSQL_HOST` | `localhost` | MySQL 地址 |
| `MYSQL_USER` | `rentagent` | 数据库用户 |
| `MYSQL_PASSWORD` | `rentagent123` | 数据库密码 |
| `REDIS_HOST` | `localhost` | Redis 地址 |
| `JWT_SECRET` | 见 application.yml | JWT 密钥（生产务必覆盖，≥ 64 字符） |
| `AES_KEY` | 见 application.yml | 身份证号加密密钥（Base64 的 16/24/32 字节） |
| `CORS_ORIGINS` | localhost/127.0.0.1 的 5173/4173 | 跨域白名单，逗号分隔 |
| `UPLOAD_DIR` | `./uploads` | 房源图片上传目录 |

### 4.2 AI 配置（核心，必读）

系统 **不绑定任何模型厂商**，通过协议适配网关接入。三种配置方式（生效优先级从高到低）：

1. **管理后台可视化配置（推荐）**：登录管理员账号 → 「AI 供应商配置」页面，添加/切换
   DeepSeek、OpenCode、CommandCode 等供应商，保存即入库并热生效，无需重启。
2. **环境变量预置命名后端**：`AI_BACKEND=<name> AGGREGATOR_API_KEY=<key> mvn spring-boot:run`
   （`AI_BACKEND` 取值见 `application.yml` 的 `ai.backends`，如 `dlut-deepseek` / `opencode-go` /
   `commandcode-chat` / `claude-messages`）。
3. **快捷单后端**：直接设 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` / `AI_PROTOCOL`。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AI_BACKEND` | `dlut-deepseek` | 生效的命名后端 |
| `AI_PROTOCOL` | `openai-chat-completions` | 协议：`openai-chat-completions` / `anthropic-messages` / `openai-responses` |
| `AI_BASE_URL` | `http://aigw.dlut.edu.cn/v1` | 模型端点 |
| `AI_API_KEY` | 空 | 模型凭据 |
| `AI_MODEL` | `DeepSeek-V4-Flash-0731-W8A8` | 模型名 |
| `AI_MAX_TOKENS` | `4096` | 单轮 token 上限（推理模型思维链计入，勿调得过小） |
| `AI_EMBEDDING_BASE_URL` / `_API_KEY` / `_MODEL` | 空 / 空 / `bge-m3` | 词嵌入（RAG）配置 |
| `AI_EMBEDDING_THRESHOLD` | `0.58` | 知识库相似度阈值 |

> **换模型只改 `AI_MODEL`（或命名后端的 `model`），不改代码；协议不同时改 `AI_PROTOCOL`。**
>
> **重要约束**：AI 能力必须接真实模型，未配置或调用失败统一返回 `4001` 并附原因，**不做任何规则/模拟兜底**。
> 不配 Key 时 AI 相关功能会明确报 4001，其余业务功能（房源、预约、签约、审核等）正常。

## 七、常见问题（FAQ）

| 现象 | 原因与处理 |
| --- | --- |
| 登录无反应 | 前端用 `127.0.0.1` 访问，被 CORS 拒绝；改用 `localhost` |
| AI 接口返回 4001 | 未配置模型或凭据无效；去管理后台配供应商，或注入 `AI_API_KEY` |
| 空库首启后端就绪但登录被锁 | 种子数据尚未提交；用 `curl "localhost:8080/api/v1/houses?size=1"` 轮询到 `total≥1` 再登录，勿反复尝试登录 |
| `docker compose down -v` 后数据丢失 | `-v` 会连种子库一起删；重新 `up` 会自动重建 |
| 推理模型回答为空 | `max_tokens` 过紧被截断；调大 `AI_MAX_TOKENS` |
| 聚合网关流式被截断 | 网关按 UA 放行；确认 `application.yml` 已覆盖 `user-agent` |

## 八、部署（服务器）说明

单机 Docker Compose 部署：`docker compose up -d --build`（Nginx + 前端静态资源 + 后端 + 数据库）。
对外部署需注入 `JWT_SECRET`、`AES_KEY`、AI 凭据等敏感变量（勿提交到仓库）；桌面端以 `file://` 加载，
后端地址用 `RENTAGENT_API_BASE=http://<host>:8080 ./RentAgent-1.0.0.AppImage` 覆盖。
